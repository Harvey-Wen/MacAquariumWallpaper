# 透明海洋桌面与鱼群交互方案

日期：2026-09-22。状态：用户已确认并实施。已验证结果和系统场景边界见 [验收记录](../../verification.md)。

## 目标与首版范围

在用户当前 macOS 壁纸上增加一层透明海洋效果。原壁纸继续由系统或用户原有程序显示，不设置桌面图片、不复制壁纸作底图，也不绘制整屏海水底色、沙地、水草缸或珊瑚背景。没有鱼和特效的区域完全透明。退出应用即移除覆盖层。

保留参考视频中游鱼的立体感、自然摆尾与转向。水纹采用局部低透明度焦散亮纹、缓慢漂移的光斑和交互涟漪；少量气泡用于提示流动，不让效果长期遮满壁纸。水纹是叠加的花纹，不对原壁纸像素进行真实折射。

默认先服务当前主屏，跟随主屏和分辨率变化重新布局；不同显示器各自独立运行的多屏功能不纳入首版完成承诺。系统全屏应用与普通应用保持在桌面效果上方。复用天气项目当前的系统合成原则：半透明系统材质如何透出壁纸，就如何透出鱼群，不按窗口矩形把画面切成洞。

## 鱼类与运动

采用侧视为主、可见少量俯视角的浅景深构图，鱼身可转向，有鳍和尾部形变；不把所有鱼做成同一形状再换色。

| 生物 | 初始数量 | 外形与行为 |
| --- | --- | --- |
| 银蓝色小型群游鱼 | 18 | 细长鱼身，群体保持间距，方向轻微错开；受惊时迅速分散 |
| 小丑鱼 | 4 | 橙白条纹、圆润体形，短距离巡游，摆尾较明显 |
| 蓝吊鱼 | 3 | 扁平蓝色鱼身和黄色尾部，宽弧线游动 |
| 蝶鱼 | 3 | 黄色高体形、深色条纹，速度中等，常两三只交错游动 |
| 蝠鲼（按用户“蝙蝠鱼”理解） | 1 | 展翼轮廓和长尾，胸鳍起伏，慢速滑翔，转向和避让更舒缓 |

合计初始 29 只。体型和速度按种类区分，个体相位与轨迹错开；数量是首版调校起点，可为视觉与性能适量调整。鱼在画面内有深度和大小差别，大型生物不长期停在同一区域。鱼群保持最小间距并平滑绕回边界，不瞬移、不穿过屏幕边缘后突然出现在另一侧。

这里是审美性的混合海洋展示，不模拟真实物种生态共存。

## 鼠标交互

| 动作 | 效果 | 恢复行为 |
| --- | --- | --- |
| 鼠标靠近 | 邻近鱼轻微避让，远处不响应 | 指针离开后缓慢恢复原方向 |
| 左键点击露出的桌面 | 点击处扩散 1–2 道柔和涟漪，附近鱼背离点击点加速 | 受惊强度随距离衰减，数秒内回到正常速度并重新聚群 |
| 按住左键拖动 | 沿路径形成短暂水流和细小气泡，邻近鱼侧向避开流动路径 | 松开后水流衰减，避免整个鱼群永久堵在角落 |
| 连续点击/快速拖动 | 可叠加局部扰动，强度与同时存在数量设上限 | 所有效果有生命周期，不无限累积 |

默认是扰动水流，不是抓起鱼拖拽，不增加投食和养成系统。桌面图标点击、双击、拖动和框选照常交给 Finder。点击图标附近也可以惊动附近的鱼，不吞掉桌面操作。

监听只用于当前可见桌面区域：普通应用窗口、Finder 文件窗口、菜单栏和 Dock 中的操作不触发海洋交互。拖动从桌面进入应用区域时结束水流；从应用开始的拖动不应被误认为桌面手势。普通窗口遮挡几何用于输入判断，不能用于裁剪鱼群画面。窗口信息不可靠时，暂时停用对应交互，保留自然游动与系统合成。

## 方案比较与推荐

| 方案 | 优点 | 代价与限制 |
| --- | --- | --- |
| AppKit 透明桌面窗口 + 原生 Metal 渲染（推荐） | 可保留真实透明背景，绘制轻量 3D 鱼身、摆尾和水纹，不依赖网页后台渲染行为 | 需要编写鱼类网格、动画与着色；先完成透明原型验收 |
| AppKit + SpriteKit | 透明层简单，适合二维/有体积明暗的鱼和粒子，开发量较低 | 立体转身和蝠鲼的立体翼面表现较弱 |
| 改造作者的 Three.js / WKWebView 项目 | 接近原视频，可参考现有群游和海水鱼 | 原项目是不透明整缸场景，宿主还使用了 WebKit 遮挡检测开关；透明与后台动画都要另行验证，直接安装会带入壁纸/登录项行为 |

推荐第一种，参考已有天气项目的窗口层级与生命周期，只提取必要的设计，不复制定位、天气数据或桌面物体碰撞系统。新项目独立运行。

## 组件与数据流

1. **桌面宿主**：菜单栏应用创建无边框、无阴影、不激活焦点的透明窗口。初始层级沿用天气项目 `desktopWindow + 1`；设置点击穿透与跨桌面行为。先验证真实桌面层级，不能把该偏移视为所有系统的保证。
2. **交互采集**：使用只监听鼠标的 NSEvent 全局事件监视器接收 down/drag/up，保持原事件继续送达 Finder。点击使用事件的实际坐标，正确转换到当前屏幕；位置采样仅用于平滑悬停，不以按钮状态轮询判断点击，避免漏掉短按。
3. **鱼群模拟**：维护位置、速度、朝向、种类与受惊状态；群游、分离、边缘避让和鼠标扰动组合成加速度；限制速度、转向和单帧时间步，恢复时避免跳动。
4. **透明渲染**：Metal 视图清屏 alpha 为零、底层非不透明；只渲染程序化鱼类网格、水纹、气泡和局部光影。鱼身各部位有独立轮廓和形变，透明鳍不应产生整片不透明矩形。使用预乘 alpha 一致的混合避免黑边。
5. **控制与生命周期**：菜单栏提供开启/关闭、暂停/恢复、交互开关、水纹强度和退出；暂停冻结画面，关闭隐藏图层。默认 30 FPS；休眠停止更新，唤醒尊重原先状态；支持系统“减少动态效果”。不自动添加登录项。

全局事件监听只观察副本，不修改原输入；不监听键盘、不获取屏幕像素。首版不主动要求辅助功能或屏幕录制。此为基于 API 的方案，目标系统上的事件可用性和窗口信息必须实测；若不满足，要明确报告，不能把悬停冒充点击交互。

## 错误与性能边界

- GPU 初始化或着色器加载失败时关闭显示层并在菜单中说明原因，不能用黑屏填满桌面。
- 屏幕变化时重建坐标和渲染尺寸，清除过时拖动；退出清理窗口、计时器及事件监听。
- 鱼、气泡、水纹均有数量上限；锁屏/休眠停止绘制。主屏 30 FPS 为目标，不预先承诺具体 CPU/GPU 占用。
- 先在当前机器测定帧耗时、内存和 10 分钟运行稳定性。默认质量以原壁纸清晰、鱼身可辨认和交互流畅为准。

## 实施与验收

1. **透明桌面原型**：编译启动；更换系统壁纸可即时透出；检查原壁纸配置未改变；图标点击、框选与拖动正常；普通窗口位于其上；退出后无残留。通过后提交 Git。
2. **鱼类与水纹**：五种形态可辨；鱼身转弯、摆尾与蝠鲼翼面连续；暗/亮两类测试底图无黑底和 alpha 黑边；连续运行无明显边界跳跃；水纹强度受控。通过后提交 Git。
3. **点击与拖动**：短点击均产生一次局部涟漪；鱼按距离分散且恢复；快速拖动有连续水流；图标仍可双击/拖动；操作普通应用不触发；离开桌面或松开后没有粘连。通过后提交 Git。
4. **生命周期与性能**：开启、暂停、关闭、恢复和退出行为一致；Space 切换、显示桌面、Mission Control、全屏、主屏变化及休眠唤醒不出现黑底或抢焦点；记录未能覆盖的环境。通过后提交 Git。

自动测试重点是模拟稳定性、距离衰减与恢复、屏幕坐标转换和输入过滤；透明合成、真实鼠标穿透和系统空间行为必须实机验证，不能只依赖截图或单元测试。
